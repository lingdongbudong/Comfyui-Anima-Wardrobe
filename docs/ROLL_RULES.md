## 一、触发方式

### 1. 节点按钮（推荐，一次性抽取）

在 **Anima 角色造型台** 节点上，预设按钮行上方有六个按钮：

| 按钮 | 动作 | 写入的槽 |
|---|---|---|
| **一键服装** | 抽一套搭配合理的服装 | `clothing_tags` |
| **一键场景** | 抽一个与服装曝光度相容的场景 | `scene_tags` |
| **一键随机搭配** | 同时抽服装 + 姿势 + 表情 + 场景，并保证互相合理 | `clothing_tags` + `pose_tags` + `expression_tags` + `scene_tags` |
| **一键姿势** | 按等级随机抽一个姿势 | `pose_tags` |
| **一键表情** | 表情随当前姿势/服装自动匹配（也可纯随机） | `expression_tags` |
| 清空 | 清掉角色 / 服装 / 姿势 / 表情 / 场景五个槽 | — |

点击后结果**直接写进对应的文本框**，可继续手工增删；节点底部显示本次的判据与校验结论。

按钮用的等级取自节点上的两个控件：`roll_level` 与 `allow_public`。
**`roll_level` 决定抽什么级别的内容，这是最重要的一个开关。**

### 2. 节点自动化（`Anima 一键随机搭配`）

需要"每次出图都换一套"时用这个节点：
把上游文本接到 `opt_prompt`，输出 `text` 接回链路即可，工作流每跑一次就重抽一次。

- `seed = -1` → 每次随机；填固定值可复现
- 它的结果按**插件层**写入，所以会压过正文里的散落服装词，
  但**不会覆盖上游插件已写的服装**（粘性槽先写锁定仍然生效）

### 3. HTTP 接口

```http
POST /anima-wardrobe/roll
{"section": "outfit|scene|pose|expression|all", "level": "sfw|suggestive|explicit|any",
 "seed": 123, "allow_public": false, "place_hint": "浴室"}
```

`seed` 省略即随机。返回 `{outfit, scene, pose, expression, level, text, violations, seed}`
（`pose`/`expression` 只在 `section=all` 或各自单独抽取时返回）。
`GET /anima-wardrobe/roll-options` 返回可选项范围（等级、场所清单、槽位容量）。

```http
POST /anima-wardrobe/girl
{"pool": "热门 TOP200", "count": 1, "huge_breasts": true, "seed": 123}
```
`huge_breasts=true` 时抽出的角色体型强制为 `huge breasts`。

## 二、可选项范围

### 抽取等级（`roll_level` / `level`）

**控件值就是合法等级 key**（中文只由 `locales/*/nodeDefs.json` 的 `values` 映射显示），
对应 NSFW 五级标度，既做上限也做保底：

| 控件值（合法 key） | 界面显示 | 目标级别 | 抽出来的内容 |
|---|---|---|---|
| `sfw` | 0 · 全年龄 | 0 | 无任何暴露向标签 |
| `suggestive` | 1 · 擦边（默认） | 1 | 裁剪镂空 / 露肩 / 短裙 / 内衣轮廓 |
| `explicit` | 2 · 成人 | 2 | 全裸 / 性器官 / 乳头 / 透视 / 半脱 / 内衣外露 |
| `hardcore` | 3 · 过激 | 3 | 性行为 / 性道具 / 束缚调教 / 体液事后 |
| **`extreme`** | **4 · 极端（新增）** | **4** | **群体多人 / 极端插入扩张 / 拘束装置 / 极限体液 / 主奴标记** |
| `any` | 不限 | 顶格 | 全池随机 |

**语义 = 上限 + 保底**：池子先按目标级别封顶（`_pool_allowed`），抽完再按目标级别补足（`_boost`）。
两者用的是**同一个判定函数**，不会出现「擦边档抽出成人内容」。

> ⭐ **宁可差档，绝不超档**：`_boost` 只收「恰好等于目标级别」的标签。
> 实测 3600 次（五档 × 公开/非公开 × 单女/双女）：命中 **99.89%**，**超档 0 次**，
> 违规 **0 次**，4 次往安全方向差了一档。

> ⚠️ **接口兼容**：老工作流里的中文标签（`"1 · 擦边"`）、数字（`"4"`）、
> 旧英文 key（`"nsfw"`）都会被 `resolve_level()` 归一成合法 key，
> **不会**再出现「level 只能取 (…) 之一」的报错。

## 三、判定标准

### ① 服装搭配合理性 —— `validate_outfit()`

| 规则 | 内容 |
|---|---|
| **主体六选一** | 整套制服/造型、连衣裙·连体、(上装+下装)、泳装、内衣套装、全裸 —— **只能命中一种** |
| **数量上限** | 袜≤1、鞋≤1、配饰≤2、材质≤2、状态≤2、道具≤2 |
| **丝袜 ⨯ 光脚** | 有 `pantyhose`/`stockings`/`thighhighs` 就不能 `barefoot`（除非 `torn pantyhose`） |
| **内衣套装 ⨯ 无内裤** | `lingerie`/`babydoll`/`negligee`/`chemise` 与 `no panties`/`bottomless` 互斥 |
| **全裸 ⨯ 主体服装** | `completely nude` 时不得有任何主体服装；**但袜/鞋/配饰/材质/状态/道具都允许**（`completely nude, naked jacket, high heels` 是经典搭配） |
| **材质必须有依附** | 只写 `see-through` 而没有任何主体服装 = 违规（全裸主体因此**不再抽材质**，从源头消除） |
| **E1 装置需行为承载**（第 5 级） | 有 `device`（拘束/装置）就必须有 `act`（极端行为）或穿着状态，不允许孤立装置 |
| **E2 极端档主体收窄**（第 5 级） | 第 5 级不与「内衣套装 / 泳装」主体并存（与装置+行为语义冲突） |

**组成方式**：先选主体形态（六选一），再依次叠加 袜 → 鞋 → 配饰 → 材质 → 状态 → 道具
（第 5 级额外叠加 极端行为 → 拘束装置 → 极限体液，装置与行为成对抽取），
最后过一遍 `repair_outfit()` 定点修复 + 再校验，确保**输出一定是 0 违规的**。

> 兜底删除顺序 `DROP_FIRST`：装饰性槽（其他/状态/材质/配饰/道具/袜鞋）先让路，
> **第 5 级专属槽排在其后**（保护目标内容），主体槽最后 ——
> 避免「为了修一个材质违规，把整轮的目标等级一起删掉」。

> ⚠️ 场景词表里混着被 NSFW 命中的词（`chains` / `exposed` / `outdoors`），
> 出场景时也会按等级上限统一过滤，否则「全年龄档」会被地牢的 `chains` 顶到过激级。

> 每个标签的槽位归属由两级判定：`presets/attire_slots.json`（Danbooru `tag group:attire`
> 的分组快照，389 词，权威表优先）→ 关键词规则兜底。
> 对 Skill 的 798 个服装标签实测覆盖率 **97%**，其余 23 个是混进服装文档的姿势/场景词。

### ② 场景合理性 —— `validate_scene()`

| 规则 | 内容 |
|---|---|
| **S1 隐私等级承载** | 场所的隐私等级必须放得下服装的暴露等级。2 级起只落**私密**或**特殊**场所；第 5 级同样只在私密/特殊（实测 60/60）；半公开/公共场所需要 `allow_public` |
| **S2 室内无天气** | 室内场所不出现雨/雪/雾/路面/城市景观描写（`rain`/`snow`/`fog`/`wet pavement`/`rainy cityscape`）。⚠️ 用词边界匹配，否则 `train`（电车）会被 `rain` 误伤 |
| **S3 过激细节匹配** | `used condom`/`cum on sheets`/`sex toy nearby` 这类细节只在 **3 级起**出现 |
| **S4 极端细节匹配**（新增） | `sex machine`/`bondage furniture`/`suspension bar`/`dungeon` 等第 5 级专属场景细节，**只有第 5 级**才有 |

**组成方式**：场所（1 个，按等级承载力过滤）→ 天气时辰（≤1，室内自动剔除天气类）→ 场景细节（≤1）。
场景的等级直接取自**同一轮抽出的服装等级**（规范等级 key，不再是三档投影），
所以「一键随机搭配」天然是自洽的。

### ③ 成人裸露向分级 —— `grade_nsfw()`（唯一真源）

**全插件只有一个判定真源** `_nsfw_core()`，对外这些函数都是它的投影：
`grade_nsfw`（0–4 级 + 分类）、`grade_explicitness`（三档兼容）、`strip_nsfw`、`_pool_allowed`。

判定顺序（命中即返回）：

```
1. 命中 群体/极端插入扩张/极端拘束装置/极限体液/主奴标记  → 4 极端
2. 命中 性行为/性道具/束缚/体液                         → 3 过激
3. 否则 取 max(基线, 命中分类的最高等级)                → 0/1/2
   基线：explicit 表命中 → 2；suggestive 表命中 → 1；否则 0
4. 无任何命中 → 0 全年龄
```

`grade_explicitness()` 保留为**三段式投影**（0→`sfw`、1→`suggestive`、≥2→`explicit`），
供旧调用方使用；**它不再自己判一套**。

| 等级 | 口径 | 典型标签 |
|---|---|---|
| **sfw** | 无任何暴露向标签 | `school uniform` / `thighhighs` |
| **suggestive** | 没有直接裸露，但透视、裁剪、镂空、半脱、掀起、内衣外露、湿身 | `see-through shirt` / `micro skirt` / `off shoulder` / `open shirt` / `lingerie` / `no bra` / `wet clothes` / `upskirt` |
| **explicit** | 画面里能直接看到性器官 / 乳头 / 全裸 | `completely nude` / `pussy cut` / `nipples` / `no panties` / `bottomless` / `pasties` |
| **hardcore** | 性行为 / 性道具 / 体液 / 束缚调教 | `deepthroat` / `vibrator` / `used condom` / `blindfold, ropes` |
| **extreme（新增）** | 群体多人 / 极端插入扩张 / 拘束装置 / 极限体液 / 主奴标记 | `group sex` / `fisting` / `suspension` / `peeing` / `branding` |

**三个刻意的设计决定：**

1. **`EXPLICIT_PATTERNS` 模糊匹配是必需的**。只做精确匹配会漏掉
   `ofuda on pussy`、`tape on pussy` 这类复合写法（实测就是这么漏的）。
2. **不做「多个暗示标签叠加就升级」的启发式**。那会让「suggestive 档」抽出被判为
   explicit 的内容，档位与结果自相矛盾。分级 = 逐标签表的并集，**规则可预期、可复现**。
3. **第 5 级分类的标签与低等级表互不重叠**，所以同一批词不会因为新档位被"顺手升级"
   （比如 `tribadism` 仍是 3 级，`fisting` 才是 4 级）。

**例外表 `EXPLICIT_EXCEPTIONS`**：`covered nipples` / `nipples covered` 虽含 `nipple`
字样，但语义是"被遮住"，判 sfw。

### ④ 姿势分层 —— `roll_pose()` / `_pose_cands()`

姿势按 NSFW 等级**分层抽取**，两级过滤：

| 层 | 规则 |
|---|---|
| **组级过滤** | 每个姿势组标 `min_level`（见 `POSE_GROUP_MIN_LEVEL`），只从 `min_level ≤ 目标等级` 的组里抽 |
| **标签级过滤** | SFM 日常姿势里混着「性暗示手势」（`cunnilingus gesture` 等），组级 min_level=0 挡不住，故对每个标签复用 `_pool_allowed` 精确过滤 |
| **加权** | `min_level` 越接近目标等级权重越高（差 0 档=4 / 差 1 档=2 / 差 2=1 / 差 3=0.5），使 hardcore/extreme 档主要抽性行为姿势、偶尔落到日常姿势 |

等级分布：`sfw` 只出日常姿势；`suggestive` 日常+诱惑；`explicit` +暴露/展示；`hardcore` +性行为组；`extreme` +过激/多人。

### ⑤ 表情自动匹配 —— `match_expression()`（数据源 = Skill 60-expression.md）

表情**跟着「当前在做什么」走**，三层决策，规则清晰可复用：

```
① 动作语义识别：从姿势/服装/关系标签里匹配触发词 → 命中情绪类型
   （自慰/口交→愉悦；高潮/痉挛→失神；束缚/被迫→抗拒；
     露出/被撞见→羞耻；骑乘/主导→得意；睡奸/催眠→无意识）
② 强度定档：NSFW 0→平静 / 1→诱惑·羞耻 / 2→愉悦 / 3→失神(重) / 4→崩坏(极限)
③ 输出：表情标签 ≤3 个；Lv3 起强制叠加 ≥1 个身体反应标签
   ⚠️ 表情标签同样不超档（过滤 grade_nsfw > 目标等级 的词），
      否则 hardcore 档表情抽到 4 级词会把整条提示词顶超档
```

触发词 → 情绪 → 标签的映射见 `wardrobe_rules.EXPRESSION_TRIGGERS` / `EXPRESSION_TAGS` / `EXPRESSION_REACTIONS`。

### 档位保级

抽完之后会复核等级：

- 目标 `explicit`/`hardcore`/`extreme` 但没到级 → 从池子里挑一个「加进去不产生新违规」
  的同档标签补上；仍不行则退回「全裸 + 保留原配饰/袜/鞋/极端槽」
- 第 5 级兜底优先补**极端行为**（`act`），因为孤立装置会被 E1 判违规
- 目标 `suggestive` 但只到 sfw → 同样挑一个暗示向标签补上
- 目标 `sfw` → 池子在抽取**之前**就按分级函数过滤，从源头堵死

⚠️ 池子过滤（`_pool_allowed`）**直接复用 `grade_nsfw`**，不另写一套匹配。
早期版本池过滤和分级用了两套不一致的逻辑，导致 sfw 档抽出 suggestive 内容。

## 五、已知取舍

- 词典判槽是**启发式**。`torn school uniform` 这类"破损的整件服装"会被判成**状态**槽
  （可叠加），而不是整套服装。语义上可接受，但会占用状态槽的名额。
- 场景只抽 1 个场所。想固定场所请用 `place_hint`（HTTP 参数）或直接手填 `scene_tags`。
- 场景天气词表里 `sunlight` / `moonlight` / `candlelight` / `dim lighting` / `ambient light`
  命中阿尼玛 Skill 自己的「禁止输出光线标签」表，因此**默认跳过**，面板上标橙色警告。
  这条是 Skill 内部的矛盾（§12.3 又说"允许环境天气和时辰描写"），留给你决定要不要放行。
